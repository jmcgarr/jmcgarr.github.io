## Appendix: Method

**Date:** every check ran on 2026-10-09 (US Pacific; 2026-10-10 UTC) from macOS, against `main` at `19bd103`; the branch was then rebased onto `1dfff0a`, which applied the hijacked-domain snapshots (PR #86). Scripts and raw results stayed in the agent's scratch folder and are not committed; the steps below reproduce them.

**Inputs.** Section A of [`content-2026-10-09.md`](content-2026-10-09.md) was parsed into one record per ID (file, post date, URL, "Why", snapshot, Alt). Each A.1 item was sorted by its "Why": **still responds** (404/410, soft 404, redirect to a home page: 95 items), **gone** (DNS failure, connection timeout or refusal, invalid TLS, an empty or broken server: 63), **hijacked or parked** (7), and the two owner decisions. The link text around each URL was read from the current `src/jbake/content/` files (read-only) to know what the author meant to link.

**Tools.** Python 3.14 with `requests` 2.34 and `beautifulsoup4` 4.15 in a scratch virtualenv; `curl` for spot checks; web search to find where an article moved (search results were always opened and checked, never trusted on their own).

**Finding live replacements (Part 1).**
1. Read the Wayback snapshot the old report proposes (a plain GET of the `web.archive.org/web/<timestamp>/<url>` page) to get the page's title and headings.
2. On the live site: the sitemap (`/robots.txt` `Sitemap:` lines, `/sitemap.xml`, `/sitemap_index.xml`, one level of sitemap indexes), then URL-pattern changes (dates dropped, `.html` dropped, `/authors/` → `/author/`, wiki dots → slashes, version folders), then a web search on the exact title. Where the vendor or project moved (Liquibase docs, Sonatype books, Blackboard → Anthology, Hudson → Eclipse/Jenkins, Vagrant → HashiCorp Developer, M2Eclipse → Eclipse, tigris.org → GitHub), the new domain got the same treatment.
3. Each candidate was fetched (GET, redirects followed) and its status, final URL, `<title>` and `<h1>`/`<h2>` recorded. **Confidence:** high = the same article or page (same title); medium = the same topic or page, rewritten or reorganized; low = only related.
4. Every old "Alt (live)" was fetched the same way, and its title compared with what the post links to; client-side redirects (`<meta http-equiv="refresh">`) were read from the HTML.

**Redirects (Part 2).** Each A.2 URL was fetched again (GET, redirects followed, every hop recorded) and the final page's title, headings and opening text read. Where a verdict depended on what the post originally meant, the post's own sentence around the link decided it (the Wayback Machine was rate-limiting, so no Part 2 snapshots were read). Groups: (a) same host, only `http`→`https` or `www`; (b) same host, new path; (c) same organization, new subdomain or sibling host; (d) a different site.

**Network etiquette.** GET only (no HEAD needed, no POST, no logins). Browser User-Agent. One request at a time per host, at least 1.5 s apart, and 8 s apart for archive.org (raised to 15, 30 and then 45 s); 429 and 5xx answers backed off 60 s or more (honoring `Retry-After`) and were never cached. Wayback use was limited to the availability API and snapshot **reads**; **no "save" request was made.** web.archive.org rate-limited this IP hard: after every 4–12 snapshot reads it answered 429 for 10–20 minutes, even at one read per 30–45 s. Each time, work on it stopped and resumed only after a long pause; 36 archive.org requests got a 429 in total. Search pages were plain GETs. Responses were cached on disk so nothing was fetched twice. In all, about 420 GETs were logged across both parts over 1 h 40 min (19:01–20:40 PDT), 67 of them to archive.org, plus about a dozen web searches.

**Not checked or not verifiable.**

- **Snapshot titles:** because of the Wayback rate limit, the old page's title was read for **30 of the 76** Part 1 items that have a snapshot (shown as "Old page (snapshot): …"); the rest say "Snapshot exists (not read)". For those, the old page was identified from the post's link text, the URL slug and the old report, and every live candidate was still fetched and checked. Where a snapshot was read, it was compared with the live page: A75 and A144 were downgraded to medium because the live text is rewritten.
- **Part 2 snapshots:** the availability API was used for the two items where a snapshot is recommended (R1, R46); no other Part 2 snapshots were looked up.
- **Bot challenges:** Vimeo (A72's re-upload, judged by the author's permalink and the page title), SlideShare (A151, found by search only), Medium (A220 in Part 2), Amazon (A35/A36 answered 200, content partly scripted), and X profiles (judged by logged-out titles).
- **Liquibase docs** URLs carry the release number (`community/user-guide-5-0-4/…`) and may move with the next release; the unversioned old URLs now redirect to the paid "Secure" docs.
- **Gone hosts with no successor** (1d) were not searched, as asked.
- The site was baked (`./gradlew clean bake`: 268 items, no warnings) and `build/jbake/docs` does not exist; this change touches only `docs/`.
